# roblox-game

Roblox game written as Luau files and synced into Roblox Studio with Rojo.

## Design reference

**Current direction (2026-11-26): `docs/monster_design.md`** (working title Wildbound; owner decisions are at its top). Model import steps for the owner: `docs/importing_models.md`. Imported models go in `ReplicatedStorage/CreatureModels` (outside Rojo's `Shared`). Upload flow (Claude): `open_cloud_invoke` POST `/assets/v1/assets` (Model, the GLB), poll the operation, `insert_asset` the new ID, then anchor each model, stand it upright facing −Z at the origin, set `AssetId` and `SourceHeight` attributes, and move it into `CreatureModels`. IDs go in `src/shared/CreatureAssets.luau` and `art/meshy/ledger.json`. The models arrive as packages (remove each `PackageLink` after setup, or Studio warns about modified packages), about 3.5× small (the code scales them), and Meshy GLBs face −Z like the runtime meshes. It pivots to an open-world monster-taming RPG: real-time mob combat with a team of 3 followers, 1–5★ species in 5 elements, levels plus Awakening, scrolls, turn-based PvP later. The mall stealth game below (`docs/roadmap.md`) is superseded; reuse its systems as the design doc's §12 lists.

`docs/whitepaper.md` is the owner's design white paper. Build the five loops it describes (core, progression, collection, excitement, retention) into an original game: do not copy the analysed game's name, creatures, art or map.

## Dependency rules (set by the owner, 2026-11-21)

- Every external download (tools, plugins, Luau packages, anything) must be listed in `tools.lock.json` with an exact version, publish date, URL, size and SHA-256.
- Only versions published more than 7 days ago. `scripts/fetch_tools.py` enforces this and the checksum.
- Ask the owner before adding any new dependency. Prefer writing the code over adding a package.
- Nothing is installed system-wide or user-wide. Tools live in `tools/` (git-ignored) and are restored with the fetch script.
- No Roblox free models, toolbox assets or third-party Studio plugins other than the locked Rojo plugin: they can carry scripts.
- No secrets in the repo. Roblox API keys, if ever used, stay out of git.

## Commands

- Restore tools: `python3 -I scripts/fetch_tools.py`
- Build place file: `tools/rojo/rojo build -o build/roblox-game.rbxl`
- Live sync to Studio: `tools/rojo/rojo serve` (listens on localhost only; do not pass `--address`)

## Studio MCP + Meshy (project-scoped, added 2026-11-21)

- `.claude.json` local scope for this repo holds two MCP servers: `meshy` (pinned @meshy-ai/meshy-mcp-server@0.6.12, copied from brawler) and `roblox-studio` (Roblox's own `StudioMCP` binary inside RobloxStudio.app; nothing downloaded). Studio side: Assistant > ... > Manage MCP Servers > "Enable Studio as MCP server".
- `scripts/studio_mcp.py` talks to StudioMCP over stdio (`list`, `call <tool> '<json>'`, `luau execute_luau <file> Edit|Server|Client`).
- `scripts/sync_to_studio.py [--only Name]` pushes src/ into the open place via execute_luau (fallback when Rojo isn't connected). Studio caps Script.Source at ~200k chars, hence chunked MeshData.
- `scripts/playtest.py <scenario.py>` mutes every client sound first (all Sounds into a `SoundService.TestMute` group at volume 0, re-applied while the test waits) so background tests are silent, then drives real input (character_navigation, keyboard, mouse) plus the Studio-only debug bridges `ServerStorage.WildDebug` / `ReplicatedStorage.WildClientDebug`.
- Uploads (owner OK 2026-11-26): Claude may upload **creature/monster models and their textures from `art/meshy/models/`** (and, owner OK 2026-11-27, the sound bank from `art/audio/` and map props from `art/meshy/props/models/`) to the owner's account through StudioMCP's `open_cloud_invoke` (following its `rbx-import-asset` skill), insert them into `ReplicatedStorage/CreatureModels`, and log every asset ID in `art/meshy/ledger.json`. Ask the owner to approve each batch first (uploads are permanent). Everything else stays off: no `generate_*` tools, no `insert_asset` except for asset IDs we uploaded ourselves (never Toolbox/free models), no other uploads.
- `scripts/mcp_bridge.sh "<allowed tools>" "<prompt>"` runs a headless Claude here so a session that started elsewhere can still call Meshy.

## Art pipeline

- Meshy sources: `art/meshy/` (concepts, `models/<name>/model.glb`, `ledger.json` with task ids and credits, `STYLE.md`).
- `python3 -I scripts/mesh_to_luau.py <glb> <Name> --tex 256` bakes a GLB into `src/shared/MeshData/<Name>.luau` (+ `_n` chunks). The client rebuilds it with EditableMesh/EditableImage (`src/shared/MeshLoader.luau`), so nothing is uploaded to Roblox.
- `python3 -I scripts/render_portrait.py <glb> <Name> [--preview out.png]` bakes a 160 px RGBA portrait into `src/shared/PortraitData/` for the Index and reveal card (`src/shared/Portraits.luau`).
- **Client mesh limit:** a client can hold only ~8 EditableMeshes at once, whatever their size (measured 2026-11-26; destroying the EditableMesh blanks its MeshPart). `MeshLoader` is a ref-counted pool capped at 7: every `Models.get` returns a `release` to call. All 30 species are uploaded to `CreatureModels` (2026-11-27), so the pool is only a fallback for future species until they're uploaded (owner approves each batch). UnitView only builds models within ~170 studs (260 for bosses). Screens use portraits, not viewports.

## Saving

- `src/server/Persistence.luau`: one DataStore record per player (`Wildbound_v1`, key `u_<UserId>`) with a session lock (`{job, t}`, 5 min timeout). Loads retry while another server holds a fresh lock, then take over; saves refuse to write if another server owns the lock.
- `src/server/PlayerData.luau`: `join` (load + sanitize), autosave every 60 s when dirty, `saveSoon` after summons/feeds/awakens/sales/first clears, `leave` (final save + release), `BindToClose` waits for writes.
- Studio uses a separate `Wildbound_v1_Studio` store. It needs Experience Settings > Security > "Enable Studio Access to API Services". Without it the game runs session-only and a toast says progress isn't saving.
- A failed load means that session never saves, so an outage can't overwrite good data.
- Changing the profile shape: bump `SCHEMA` in Persistence and handle old records in `PlayerData.sanitize`.
